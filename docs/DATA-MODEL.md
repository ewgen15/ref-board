# Формат даних (JSON)

Формат описано за кодом `ref-board.html` (`buildExport`, `newRef`, `normalizeRef`) і за файлом `Ref Board.json` з репозиторію. Приклад нижче синтетичний. Поля, які в прототипі ще не заповнюються або не мають UI, позначено.

## Верхній рівень

```json
{
  "version": 1,
  "exportVersion": 1,
  "exportedAt": "2026-11-12T12:44:16.116Z",
  "references": [ /* записи, див. нижче */ ]
}
```

| Поле | Тип | Опис |
|---|---|---|
| `version` | число | версія схеми. Імпорт приймає лише `1`. |
| `exportVersion` | число або `null` | номер експорту з імені файлу (`vNNN`). `null` у резервному експорті в Downloads. У `Ref Board.json` поля немає (ймовірно, ранній експорт). |
| `exportedAt` | рядок ISO 8601 (UTC) | момент експорту |
| `references` | масив | усі записи з `localStorage` (включно з тими, для яких файлу зараз немає в папці) |

Імʼя файлу експорту: `ref-board_vNNN_РРРР-ММ-ДД_ГГГГ.json` (`_ГГГГ` це година і хвилина, локальний час). Приклад: `ref-board_v001_2026-11-12_1530.json`.

## Запис референсу (`references[i]`)

```json
{
  "id": "Example Dashboard.webp|137652|1794479215994",
  "name": "Example Dashboard",
  "file": { "name": "Example Dashboard.webp", "w": 2048, "h": 1536 },
  "source": "",
  "tags": [],
  "status": "done",
  "comment": "Загальне враження.",
  "highlights": [
    {
      "id": "hmwdftnlhbzg8",
      "rect": { "x": 72.65, "y": 66.55, "w": 24.81, "h": 29.92 },
      "title": "Кольори",
      "note": "Контраст акценту на темному фоні.",
      "category": "color",
      "verdict": "take"
    }
  ],
  "palette": [],
  "font": { "interesting": false, "note": "" },
  "ratings": {
    "color":      { "score": 4, "verdict": "take",    "note": "" },
    "typography": { "score": null, "verdict": "neutral", "note": "" },
    "layout":     { "score": null, "verdict": "neutral", "note": "" },
    "components": { "score": null, "verdict": "neutral", "note": "" },
    "mood":       { "score": null, "verdict": "neutral", "note": "" }
  },
  "takeaways": { "generatedAt": null, "tokens": {}, "rules": [], "avoid": [] }
}
```

| Поле | Тип | Значення | Примітки |
|---|---|---|---|
| `id` | рядок | ключ файлу `імʼя\|розмір\|lastModified` | ключ чутливий до перезбереження файлу, див. [ARCHITECTURE.md](ARCHITECTURE.md) |
| `name` | рядок | імʼя файлу без розширення | лише відображення |
| `file.name` | рядок | імʼя файлу з розширенням | |
| `file.w`, `file.h` | число або `null` | природний розмір картинки | заповнюються після завантаження картинки |
| `source` | рядок | джерело (URL, сайт) | у прототипі немає поля вводу |
| `tags` | масив рядків | довільні теги | у прототипі немає UI, зарезервовано |
| `status` | `"draft"` або `"done"` | «оцінено» (●) чи ні | перемикається кнопкою «Позначити як оцінений» |
| `comment` | рядок | загальний коментар | вкладка «Оцінка» |
| `highlights` | масив | виділення і тези, див. нижче | |
| `palette` | масив | палітра, див. нижче | у прототипі завжди `[]` (етап 3) |
| `font` | обʼєкт | `{interesting: bool, note: string}` | позначка «шрифт цікавий» і нотатка |
| `ratings` | обʼєкт | критерії, див. нижче | ключі фіксовані |
| `takeaways` | обʼєкт | надбання (результат узагальнення) | у прототипі завжди порожній, етап 4 |

## Виділення (`highlights[i]`)

| Поле | Тип | Значення |
|---|---|---|
| `id` | рядок | випадковий: `h` + час у base36 + випадкові символи (`uid()`) |
| `rect` | обʼєкт | `{x, y, w, h}` у **відсотках** від розміру картинки (0–100), два знаки після коми |
| `title` | рядок | заголовок, за замовчуванням `Виділення N` |
| `note` | рядок | «що саме і чому» |
| `category` | рядок | `color`, `typography`, `layout`, `component`, `mood`; за замовчуванням `component` |
| `verdict` | рядок | `take` (беру), `neutral` (нейтрально), `avoid` (уникаю); за замовчуванням `neutral` |

Координати в відсотках, а не в пікселях: виділення не з'їжджають при зміні масштабу і при відкритті на іншому екрані. Мінімальний розмір при малюванні 0,5 %. Значення `x + w` і `y + h` не перевищують 100 (так поводиться інтерактивна зміна розміру; імпорт цього не перевіряє).

Поле `crop` (шлях до кропа для аналізу агентом) у прототипі відсутнє, див. етап 4а в плані.

## Оцінки (`ratings`)

Фіксовані ключі: `color`, `typography`, `layout`, `components`, `mood`. Кожен:

| Поле | Тип | Значення |
|---|---|---|
| `score` | число 1–5 або `null` | оцінка; повторний клік знімає |
| `verdict` | `take`, `neutral`, `avoid` | за замовчуванням `neutral` |
| `note` | рядок | коментар до критерію |

Плановий стан «не обрано» (щоб відрізняти «не оцінював» від «нейтрально») ще не реалізовано, див. [ROADMAP.md](ROADMAP.md).

## Палітра (`palette`)

Формат, який видає алгоритм у `color-test/` (етап 3, у прототипі ще не заповнюється):

```json
{ "hex": "#0f1115", "share": 0.52, "role": "background" }
```

- `hex`: нижній регістр, `#rrggbb`;
- `share`: частка площі від 0 до 1;
- `role`: `background`, `surface`, `accent`, `textPrimary`, `textSecondary` або `other`;
- `removed: true` (необовʼязково) позначає фон, вилучений із розрахунку решти.

Ролі в алгоритмі евристичні. Див. [COLOR-EXTRACTION.md](COLOR-EXTRACTION.md).

## Надбання (`takeaways`, етап 4)

Поля задані, але не заповнюються:

- `generatedAt`: час формування або `null`;
- `tokens`: обʼєкт токенів (наприклад, кольори за ролями);
- `rules`: масив правил (типографіка, патерни);
- `avoid`: масив «чого уникати».

Плановий формат JSON для переносу в дизайн-токени застосунку описано в [PLAN.md](PLAN.md), розділ 7.

## Сумісність і версії

- Імпорт вимагає `version === 1`. Інша версія відхиляється з повідомленням «Непідтримуваний формат».
- Імпорт зливає лише поля, відомі нормалізатору: `normalizeRef` бере значення за замовчуванням і накладає зверху те, що є у файлі. Невідомі поля зберігаються в записі, але інтерфейс їх не використовує.
- Запис з тим самим `id` при імпорті **повністю замінюється**.
- Усі імена полів англійські, тексти користувача українські. Дати в ISO 8601.
