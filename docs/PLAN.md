# Ref Board: інструмент для роботи з візуальними референсами (план)

> **Контекст:** інструмент створювався для роботи над мобільним застосунком-власником проєкту (звідси згадки `theme.ts` і стилю застосунку). Тепер він самостійний; ці згадки лишено як історичний контекст рішень.

## 1. Мета і межі
**Мета:** швидко розібрати референс (скрін UI), позначити, що подобається, оцінити його за кількома критеріями й отримати «надбання»: токени та правила, які можна перенести в дизайн-токени проєкту (`theme.ts` у застосунку-власнику).

**Входить у v1:**
- завантаження картинок (png, webp, jpg) через drag-and-drop або вибір файлів/папки;
- перегляд референсу, прямокутні виділення, до кожного теза з коментарем;
- автоматична палітра (6–8 кольорів) з ручним призначенням ролей;
- шрифт: лише проста позначка «шрифт цікавий» (або нічого) і необов'язкова нотатка. Визначення шрифту вигадаємо окремо пізніше;
- оцінка за критеріями й генерація надбання;
- експорт/імпорт JSON, експорт Markdown, автозбереження.

**Рішення після обговорення:**
- Ліворуч постійний список референсів (зображень). Для кожного зберігається все, що вибрали: тези, палітра, шрифти, оцінки. До нього можна повертатися й додавати.
- Інструмент привʼязаний до папки з референсами (довільна папка). При відкритті він пересканує папку й позначає нові файли міткою «нове». Реалізація: File System Access API (`showDirectoryPicker`, Chrome/Edge). Дескриптор папки зберігається в IndexedDB, при відкритті треба один раз підтвердити доступ. Файли зіставляються за імʼям + розміром + датою зміни. Запасний варіант для інших браузерів: додавання через drag-and-drop.
- Одна базова тема. Не визначаємо, яка саме (світла чи темна), і перемикача тем немає.
- Стиль інтерфейсу інструмента: нейтральний, як у початковому прототипі (холодний сірий фон `#f4f5f7`, білі панелі, синій акцент `#3b6fe0`, зелений/червоний для «беру/уникаю», системний шрифт, 13 px). Він не залежить від стилю застосунку-власника. Інструмент згодом виділяється в окремий проєкт, тож його оформлення лишається власним і нейтральним.
- Макет: ліворуч список референсів, праворуч одна широка колонка: велика картинка зверху на всю ширину, під нею редагування (вкладки «Тези по областях», «Загальна оцінка», «Колір»). Метадані референсу в одному тонкому рядку. Категорії та вердикти тез вибираються чіпсами з емодзі, а не дропдаунами.
- Загальна оцінка: великі картки-характеристики з ілюстраціями (колір, шрифт, компоненти, сітка, настрій). Коментар розгортається лише в обраної картки.
- Колір: витягування палітри (k-means). Для референсів із домінантним фоном (>50 %) фон вилучається, а частки рахуються по залишку; є режим «з виділення» та піпетка. Ролі лише підказка, їх можна виправити вручну. Код: `tools/ref-board/color-test/`.
- Зведеного висновку по всіх референсах у v1 немає. Підсумок тільки по кожному референсу окремо; зведення потім робитиме агент на основі експорту, а флоу уточнимо з часом.

**Не входить у v1:** темна тема, зведений підсумок по всіх референсах, OCR і точне розпізнавання шрифту, хмара і спільна робота, порівняння кількох референсів поруч, полігони й стрілки, синхронізація з Figma.

**Самодостатність:** інструмент живе в окремій папці (`tools/ref-board/`), нічого не імпортує з проєкту і нічого в ньому не змінює. Проєкт отримує тільки експортований файл.

## 2. Підхід і стек
Один файл `ref-board.html` (vanilla JS + CSS, без збірки й без npm). Відкривається подвійним кліком або через `npx serve`. **Чому:** такий файл легко перенести в інший проєкт, і йому нічого не треба встановлювати, а потрібних функцій (canvas, IndexedDB, File API) браузеру досить.

- **Метадані** (виділення, оцінки, палітра, надбання) зберігаються в `localStorage`.
- **Самі картинки** зберігаються в IndexedDB як Blob, бо `localStorage` вміщує близько 5 МБ, а один PNG у наборі референсів уже важить 5,3 МБ. Якщо IndexedDB не потрібен, є запасний варіант: зберігати тільки ім'я файлу й розміри та прикріплювати файл заново після відкриття.
- **Експорт/імпорт:** `ref-board.json` (без картинок або з опцією вбудувати base64) і `ref-board.md`.

## 5. Витягування кольорів і шрифтів
**Кольори** (власний алгоритм, без бібліотек):
1. Картинку малюємо на прихований canvas, зменшений до ~200 px по довшій стороні, і читаємо пікселі через `getImageData`.
2. Квантизуємо: кожен канал округлюємо до 5 біт (32 рівні) і рахуємо частоту кожного «кошика».
3. Кластеризуємо k-means (k = 8, близько 10 ітерацій). Кластери, ближчі за ΔE ≈ 8 (у Lab або хоча б у зваженому RGB), зливаємо.
4. **Автоприпущення ролей:** найбільша частка дає `background`. Найближчий до фону колір із часткою понад 5% дає `surface`. Найнасиченіший колір із малою часткою дає `accent`. Найконтрастніший до фону дає `textPrimary`, проміжний за яскравістю дає `textSecondary`. Решта отримує `other`. Ролі потім правляться вручну через випадаючий список.
5. Палітру можна рахувати й **по виділенню**: той самий алгоритм у межах `rect`. Це корисно, щоб узяти колір конкретної кнопки. Піпетка додає колір точково.
6. Для пар текст/фон показуємо контраст WCAG (формула відносної яскравості).

**Шрифти (спрощено у v1).** З растрової картинки шрифт надійно не визначити, тому у v1 його не визначаємо. Є лише перемикач «шрифт цікавий» і необов'язкова нотатка. Класифікація, підбір аналога з Google Fonts і Claude-підказка відкладені: спосіб вигадаємо окремо пізніше.

**Ризики й обмеження:**
- **Tainted canvas.** Якщо картинка завантажена через `<img src="file://...">` або з чужого домену, `getImageData` у Chrome кидає помилку. Тому картинки читаємо тільки через File API або drag-and-drop (`createImageBitmap(file)`): тоді canvas не «забруднюється».
- **WebP** у сучасних браузерах декодується нативно. Для старого Safari потрібна перевірка й зрозуміле повідомлення про помилку.
- **Великі PNG** (5+ МБ, великі розміри). Для аналізу кольорів зменшуємо, для показу використовуємо `object-fit` і zoom. Не тримаємо base64 у `localStorage`.
- **Тіні, градієнти, фото й ілюстрації** у референсі засмічують палітру. Тому є кнопка «аналізувати лише виділене» і ручне видалення кольорів.

## 6. Система оцінки і надбання
Критерії (вкладка «Оцінка»), по кожному: вердикт **беру / нейтрально / уникаю**, шкала 1–5 і короткий коментар.

| Критерій | Про що |
|---|---|
| Кольори | палітра, контраст, використання акценту |
| Типографіка | ієрархія, розміри, вага, цифри |
| Сітка і відступи | ритм, щільність, радіуси |
| Компоненти | картки, кнопки, графіки, індикатори |
| Настрій | загальне враження, відповідність продукту |

Окрім цього, кожне виділення має власний вердикт. Так виходить оцінка окремих елементів.

**Як формується надбання** (кнопка «Сформувати», результат можна редагувати):
- **Токени кольорів:** беруться з палітри, якщо «Кольори» мають вердикт `take`. Ролі стають ключами токенів.
- **Типографіка:** клас, аналог і правила з тез категорії `typography` з вердиктом `take`.
- **Патерни компонентів:** тези з категорій `component` і `layout` з вердиктом `take`, кожна з посиланням на виділення.
- **Чого уникати:** усі тези й критерії з вердиктом `avoid`.
- **Пріоритет:** критерії з оцінкою 4–5 йдуть першими. Те, що має оцінку 1–2 і вердикт не `avoid`, позначається як «сумнівне».

## 7. Формат експорту
**JSON** (`ref-board.takeaways.json`). Це плаский об'єкт, який можна майже напряму влити в `theme.ts`:
```json
{
  "colors": { "background": "#0F1115", "surface": "#1A1D24", "accent": "#C6F432",
              "textPrimary": "#F2F3F5", "textSecondary": "#8A8F98" },
  "typography": { "family": "Inter", "class": "neo-grotesque", "numericFamily": "Space Grotesk" },
  "patterns": [{ "name": "Stat card", "rule": "Велике число + дрібний сірий підпис", "ref": "ref_01#h1" }],
  "avoid": ["Більше одного акцентного кольору на екран"],
  "sources": ["ref_01", "ref_04"]
}
```
**Markdown** (`ref-board.md`): по кожному референсу назва, вердикти по критеріях, тези списком; наприкінці зведений блок «Надбання» (кольори таблицею hex/роль/контраст, правила типографіки, патерни, чого уникати). Підходить для вставки в `plan.md` або в задачу.

Зведеного експорту по всіх референсах у v1 немає. Експорт дає окремі, добре структуровані записи по кожному референсу, щоб агент міг сам їх звести.

## 7а. Загальна картина: тези + картинки разом
**Ідея.** Тези самі по собі (оцінки, «дуже гарно») не дають глибини розуміння. Цінність з'являється, коли їх зіставляють з тим, що реально на картинці, і з усіх референсів складається спільна картина. Це робить агент (Claude), а не сам інструмент: він бачить і текст, і зображення. Перевірено вручну на першому експорті: зіставлення тез із вирізаними областями виявило і спільний знаменник, і суперечності, яких не видно з самих текстів.

**Що має віддавати інструмент для такого аналізу**
- Експорт JSON (як зараз) плюс **кропи виділених областей** як окремі PNG у тій самій папці (`ref-board_v003_crops/<ref>_<id>.png`). У JSON у кожного виділення є поле `crop` із шляхом до файлу. Агент читає тезу й дивиться на її кроп.
- Для референсу без виділень агент дивиться на повну картинку разом із оцінками й нотатками.
- Версія експорту в імені файлу дозволяє порівнювати, як змінювалося розуміння.

**Що агент має зробити (флоу, який уточнюватимемо з часом)**
1. Зіставити кожну тезу з її кропом: що саме на картинці, чи збігається категорія тези зі змістом (тип, колір, компонент, настрій).
2. Знайти **спільний знаменник**: принципи, що повторюються в різних референсах попри різні палітри (наприклад, велике число як герой екрана, один акцент для стану).
3. Назвати **суперечності**: референси, що тягнуть у різні боки (нейтральний + один акцент / яскравий мультиколір / темний + неон), і поставити користувачу одне питання, що з них найближче до продукту.
4. Зіставити з продуктом: куди кожен прийом лягає в застосунок (мотогодини, залишок пального, Start/Stop, журнал, ТО).
5. Позначити прогалини: чого бракує, щоб тези були конкретними (немає «чому», немає палітри, немає нотаток).

**Результат** — окремий документ «Загальна картина» (Markdown), який інструмент не генерує сам. Структура: принципи, суперечності й питання, відповідність екранам застосунку, прогалини. Інструмент лише готує дані (тези, кропи, оцінки, палітру).

**Що з цього випливає для інтерфейсу інструмента**
- Біля виділення потрібне поле «чому це працює» (одне речення), бо без нього аналіз лишається на рівні настрою.
- Вердикт «не обрано» як окремий стан за замовчуванням, щоб відрізняти «не оцінював» від «нейтрально».
- Кнопка «Експортувати для аналізу» записує JSON і кропи разом.

## 8. Етапи реалізації
1. **Перегляд і зберігання.** Привʼязка до папки, пересканування з міткою «нове», список із мініатюрами, показ референсу з zoom, IndexedDB + `localStorage`, експорт/імпорт JSON. *Готово, коли* 11 референсів із папки додаються, переживають перезавантаження сторінки і відновлюються з JSON у чистому браузері.
2. **Виділення і тези.** Малювання, переміщення й видалення прямокутників, нумерація, панель тез із категорією і вердиктом. *Готово, коли* виділення лишаються на місці при zoom і після імпорту.
3. **Палітра.** k-means по всій картинці й по виділенню, автоприпущення ролей, ручна правка, піпетка, контраст. *Готово, коли* для темних дашбордів фон/поверхня/акцент визначаються правильно щонайменше в 8 з 11 референсів без ручної правки.
4. **Позначка шрифту, оцінка, надбання й експорт MD/JSON.** *Готово, коли* з одного повністю оціненого референсу виходить JSON, який вручну переноситься в `theme.ts` без додаткових правок структури.
4а. **Підготовка даних для аналізу агентом** (розділ 7а): експорт кропів виділень поруч із JSON, поле «чому це працює», стан вердикту «не обрано». *Готово, коли* агент, маючи лише папку експорту, може зіставити кожну тезу з картинкою без звернення до оригіналів.
5. *(Можна відкласти)* **Вибір папки, з якою працювати** (фіча на потім): перемикання між кількома папками/проєктами, список останніх папок, окремі дані для кожної. У v1 інструмент працює з однією папкою. Також відкладено: інтеграція з Claude API, зведення по кількох референсах, порівняння поруч, теги й фільтри, винесення в окремий репозиторій.

## 9. Відкриті питання
Закрито: теми (одна базова, без перемикача), зведений підсумок (ні, пізніше), токени кольорів (плоскі ролі, без розподілу на light/dark), «ентіті» у списку зліва (це самі референси; кольори, компоненти й шрифти живуть на вкладках справа), картинки (не зберігаємо в IndexedDB, читаємо з папки за дескриптором).
Відкритих питань наразі немає. Шрифти: у v1 лише позначка «цікавий»; спосіб визначення вигадаємо окремо.
