# Архітектура ref-board.html

Прототип це один HTML-файл (~44 КБ): CSS у `<style>`, JavaScript у `<script>`, без збірки, без npm і без зовнішніх бібліотек. Уся логіка загорнута в IIFE з `'use strict'`, назовні нічого не експортується. Файл можна відкрити в будь-якому місці, де працює локальний сервер.

## Розкладка сторінки

| Зона | Елемент | Призначення |
|---|---|---|
| `aside.left` | `#folderBar`, `#list`, `.foot` | папка, список референсів, експорт і імпорт |
| `main.center` | `.toolbar`, `#vp` > `#stage` (`img` + `#ov`) | режими «Виділити» / «Перегляд», масштаб, картинка з накладеними виділеннями |
| `aside.right` | `#tabs`, `#panel` | вкладки «Тези», «Оцінка», «Колір» (заглушка) |

CSS-grid: `260px | 1fr | 340px`, мінімальна ширина `900px`. Кольори винесено в CSS-змінні `:root` (`--bg`, `--accent`, `--take`, `--avoid` тощо): це нейтральна тема з плану.

## Стан у пам'яті (`S`)

Об'єкт `S` тримає рантайм-стан і не зберігається:

- `supported` (є `showDirectoryPicker`), `handle` (дескриптор папки), `permOk` (є доступ на читання), `writeOk` (є доступ на запис);
- `files`: `Map` ключ → `{key, name, file, url}`. `file` це `File` з папки або доданий вручну, `url` це `URL.createObjectURL`;
- `cur` (ключ відкритого референсу), `tab` (`tags` / `rating` / `color`), `mode` (`draw` / `pan`), `sel` (id виділення);
- `draft` (прямокутник, що малюється), `drag` (поточне перетягування), `scale`, `fit`, `natW`, `natH` (розміри картинки).

Збережений стан (`store`) окремо: він лежить у `localStorage` (див. нижче) і переживає перезавантаження.

## Ключові функції за назвами

Нижче функції за назвами з коду, згруповані за відповідальністю.

**Константи і чисті функції (експорт назв)**
- `IMG_RE = /\.(png|jpe?g|webp)$/i`: які файли вважаються референсами.
- `EXPORT_RE = /^ref-board_v(\d+)_.*\.json$/`: які файли вважаються експортами.
- `nextVersion(names)`: найбільший номер версії + 1 (0, якщо експортів немає).
- `stampOf(date)`, `exportName(version, date)`: імʼя файлу `ref-board_vNNN_РРРР-ММ-ДД_ГГГГ.json` (локальний час).
- `fileKey(f)`: `name|size|lastModified`.
- `CRITERIA`, `VERDICTS`, `CATS`: довідники критеріїв, вердиктів і категорій тез.

**Сховище**
- `loadStore()`, `saveStore()`: читання і запис `localStorage`. Якщо JSON зіпсований, сирий рядок копіюється в ключ `ref-board:v1:broken`, а стан починається з порожнього.
- `idbOpen()`, `idbGet(k)`, `idbSet(k, v)`: IndexedDB, тільки для дескриптора папки.

**Записи (references)**
- `newRef(key, fileName)`: порожній запис із полями за замовчуванням.
- `normalizeRef(raw, key)`: доповнює імпортований запис полями за замовчуванням. Виділення копіюються як є (їх не валідовано).
- `ensureRef(key)`: створює запис для файлу, якщо його ще немає.
- `statusOf(key)`: ○ / ◐ / ●. `isTouched(r)` визначає, чи з референсом щось робили.

**Файли і папка**
- `setFiles(list, replace)`: наповнює `S.files`, створює object URL.
- `scanFolder()`: ітерує `handle.values()`, відфільтровує картинки, оновлює `scanIds` і `newIds`.
- `addFilesList(list)`: додавання вручну (кнопка або drag-and-drop).
- `pickFolder()`: `showDirectoryPicker({mode: 'readwrite', id: 'ref-board'})`, зберігає дескриптор в IndexedDB, сканує папку.
- `queryPerm(h, mode)` (без запиту дозволу), `askPerm(h)` і `requestPermission` (лише з жесту користувача), `requestWrite()`, `restoreAccess()`.

**Експорт і імпорт**
- `exportJson()`: див. розділ «Експорт» нижче.
- `listExports(h)`, `createExportFile(h, version, date)`, `buildExport(version, date)`, `fallbackExport(date, reason)`.
- `openFolderImport()` (діалог `#pickDlg`), `importFromFolder(name)`, `importJson(file)`.

**Виділення і масштаб**
- `openRef(key)`: відкриває референс, знімає мітку «нове».
- `selectHl(hid)`, `deleteHl(hid)`.
- `fitScale()`, `layoutStage()`, `setZoom(ns, cx, cy)`: масштаб зберігає точку під курсором.
- `pt(e)`: координати курсора у відсотках від картинки.
- `onDown`, `onMove`, `onUp`: малювання (`draw`), переміщення (`move`), зміна розміру (`resize`, ручки `nw/ne/sw/se`).
- `startPan(e, hid)`: перегляд мишею і клік по виділенню.

**Рендер**
- `renderAll()` викликає `renderFolderBar`, `renderList`, `renderCenter`, `renderTabs`, `renderPanel`. Оверлей виділень перемальовується через `renderOverlay()` (`innerHTML`).
- `tagsHtml(r)`, `ratingHtml(r)` будують панель справа.
- `wireEvents()` вішає делегування подій на контейнери, `init()` відновлює доступ з IndexedDB.

## Сховища

| Сховище | Ключ / назва | Що зберігається | Чому саме так |
|---|---|---|---|
| `localStorage` | `ref-board:v1` | `{version: 1, refs, scanIds, newIds, folderName}` | метадані малі, синхронні, не потребують асинхронності |
| IndexedDB | база `ref-board`, сховище `kv`, ключ `dirHandle` | `FileSystemDirectoryHandle` | дескриптор можна зберегти лише в IndexedDB (structured clone) |
| File System Access API | папка, обрана користувачем | картинки і файли експорту | картинки не потрапляють у браузерне сховище |

Структура `refs` у `localStorage`: `{ "<ключ файлу>": <запис> }`. Запис описано в [DATA-MODEL.md](DATA-MODEL.md). Картинки туди не потрапляють.

`scanIds`: ключі файлів, які були в папці під час останнього сканування. `newIds`: ключі, які з'явилися після попереднього сканування і ще не відкривали. Мітка «нове» зʼявляється в списку, а зникає після відкриття.

## Ключ файлу і його наслідки

Ключ референсу це рядок `імʼя|розмір|дата_зміни` (`fileKey`). Він визначає, чи це той самий файл:

- **Перейменування або перезбереження** файлу в редакторі змінює дату, і ключ стає новим. Тези старого ключа лишаються в `localStorage` зі статусом «немає файлу», а для нового файлу створюється порожній запис. Це відома проблема, див. [ROADMAP.md](ROADMAP.md).
- **Той самий файл на іншому комп'ютері** матиме інший `lastModified`, тож тези не зіставляться. Для переносу використовується JSON-експорт, але він прив'язаний до того самого ключа.
- **Запасний режим (без папки)** використовує той самий ключ, тож після повторного додавання того самого файлу тези відновлюються.

## Сканування папки і мітка «нове»

1. `scanFolder()` ітерує записи папки, бере тільки файли з `IMG_RE` і створює `File` через `entry.getFile()`.
2. Ключі файлів порівнюються з попереднім сканом (`scanIds`). Нові ключі (яких не було раніше) додаються в `newIds`, але тільки якщо ім'я папки не змінилося (`folderName`).
3. `newIds` очищаються від ключів, яких більше немає в папці.
4. Скан запускається при старті (якщо є доступ), після «Відновити доступ» і по кнопці «Оновити».

Якщо користувач змінив папку на іншу з тим самим іменем, інструмент цього не розрізняє: мітка «нове» може бути неточною.

## Експорт JSON

1. Якщо доступу на запис немає, а папка обрана, `exportJson()` спочатку викликає `requestWrite()`. Це має бути жест користувача (клік), тому запит іде першим.
2. `listExports(h)` знаходить усі `ref-board_vNNN_*.json` у папці і визначає наступну версію (`nextVersion`).
3. `createExportFile` перебирає імена, починаючи з цієї версії, і створює перший вільний файл (наявні не перезаписує, ліміт 1000 спроб).
4. Вміст: `{version: 1, exportVersion, exportedAt, references}`, де `references` це всі записи з `store.refs`. Зображень немає.
5. Якщо запис у папку не вдався, створений порожній файл видаляється, а експорт іде в Downloads як `ref-board.json` (з `exportVersion: null`).

Приклад імені: `ref-board_v001_2026-11-12_1530.json`, наступний експорт дасть `ref-board_v002_...`.

## Імпорт

- **Імпорт з папки** (`openFolderImport`): діалог зі списком `ref-board_v*.json`, від новіших. Вибраний файл читається і імпортується.
- **Імпорт JSON** (`importJson`): будь-який JSON через `<input type="file">`. Вимагає `version === 1` і масив `references`; записи без рядкового `id` пропускаються.
- Якщо серед імпортованих є записи з тим самим `id`, показується підтвердження, і вони **повністю замінюються** (не зливаються).
- Імпорт не перевіряє координати виділень (`rect`), тож некоректні значення пройдуть у дані.

Імʼя `Ref Board.json` (з пробілом) не відповідає `EXPORT_RE`, тому він не зʼявиться в діалозі «Імпорт з папки». Його можна імпортувати через «Імпорт JSON».

## Fallback без File System Access API

Якщо `showDirectoryPicker` відсутній (`S.supported === false`):

- панель папки показує повідомлення, а кнопка «Додати файли» працює;
- файли живуть тільки в `S.files` (object URL), після перезавантаження їх треба додати знову;
- тези й оцінки в `localStorage` зберігаються, бо привʼязка йде за ключем файлу;
- експорт завжди іде в Downloads (`fallbackExport`).

## Події і рендер

- Список, вкладки, панель і `folderBar` використовують делегування подій: один обробник на контейнер (`closest('[data-...]')`).
- Зміни полів панелі (`input`) пишуть в запис одразу і викликають `saveStore()`. Зміни вердиктів і оцінок (`change` або `click`) перерисовують список (`renderList`) і панель.
- Оверлей виділень перемальовується повністю через `innerHTML` при кожній зміні (`renderOverlay`). Для поточного розміру даних (десятки виділень на референс) це досить.
- Клавіші: `Delete` і `Backspace` видаляють вибране виділення (не в полях вводу), `Escape` знімає вибір.

## Що змінити при переносі в інший проєкт

- Нічого не зав'язано на шлях проєкту: достатньо скопіювати один файл.
- Для іншого застосунку треба змінити назви ключів (`ref-board:v1`, база `ref-board`), якщо на одному origin живе кілька інструментів.
- Тема (`:root`) відокремлена, її можна замінити без змін логіки.
