# Ref Board

Ref Board — локальний інструмент для розбору візуальних референсів (скриншотів UI): ви переглядаєте картинку, позначаєте на ній ділянки з коментарями (тези), оцінюєте референс за критеріями, а результат експортуєте в JSON. Далі цей файл можна передати агенту або людині для узагальнення.

**Статус: прототип.** Працює один файл `ref-board.html` (етапи 1–2 з [плану](docs/PLAN.md)). Вкладка «Колір» поки заглушка; алгоритм палітри окремо готовий у `color-test/` і ще не підключений до інтерфейсу. Автоматичних тестів немає.

## Навіщо

Тези самі по собі мало що дають. Цінність з'являється, коли їх зіставляють з картинкою і з іншими референсами. Тому інструмент зберігає структуровані дані (виділення, вердикти, оцінки, палітру), а узагальнення робить агент або людина на основі експорту. Мета — перенести перевірені прийоми (токени кольорів, типографіка, патерни компонентів) у дизайн-систему застосунку.

Інструмент самодостатній: нічого не імпортує з проєкту і нічого в ньому не змінює. Проєкт отримує лише експортований файл.

## Швидкий старт

1. Відкрийте термінал у папці `tools/ref-board` і запустіть локальний сервер:
   ```
   python3 -m http.server 8000
   ```
2. Відкрийте в Chrome або Edge адресу `http://localhost:8000/ref-board.html`.
3. Натисніть «Обрати папку» і вкажіть папку з референсами. Браузер попросить дозвіл на читання і запис.

Наступного разу натисніть «Відновити доступ» (браузер вимагає підтвердження жестом користувача). Якщо дозволу на запис немає, з'явиться кнопка «Дозволити запис».

**Чому локальний сервер.** Вибір папки (`showDirectoryPicker`) працює лише в безпечному контексті: `localhost` або `https`. Тези зберігаються в `localStorage`, а він прив'язаний до адреси. Тому `localhost:8000` і `127.0.0.1:8000` це різні сховища. Відкриття через `file://` у Chrome, імовірно, теж працює, але не перевірено.

**Запасний варіант (Firefox, Safari, інші браузери).** Вибір папки недоступний. Додавайте картинки кнопкою «Додати файли» або перетягуванням. Після перезавантаження сторінки файли треба додати знову, але тези зберігаються: зв'язок із картинкою йде через ключ «ім'я + розмір + дата зміни». Експорт іде в папку «Завантаження» (Downloads).

Докладніше про механізми: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Залежності від зовнішніх матеріалів

- **Референси.** Сам інструмент працює з будь-якою папкою, яку ви вкажете. Але скрипти `color-test/` і `concept/` очікують картинки за відносним шляхом `../../../Design/Referrence/` (тобто від кореня проєкту-власника). Якщо репозиторій переносять, цей шлях треба змінити або покласти референси туди ж. Шляхи в `concept/ref-board-concept.html` і `color-test/make_ground_truth.py` / `extract_palettes.py` мають ту саму логіку.
- **Авторські права.** `ground_truth.json` і `palettes.json` містять імена файлів сторонніх референсів (у іменах є імена авторів робіт). Самі картинки в репозиторій не входять і не поширюються.
- **Python-залежності** для `color-test/`: `numpy`, `Pillow`. Для тесту паритету потрібен ще Node.js.

## Обмеження і відомі проблеми

- Працює лише в Chromium-браузерах (Chrome, Edge) з повною функціональністю. В інших браузерах картинки треба додавати вручну.
- Картинки не зберігаються в браузері, лише метадані. Без папки (або без повторного додавання файлів) картинки недоступні. `localStorage` обмежений приблизно 5 МБ, тож великі дані сюди не потраплять.
- Мінімальна ширина вікна 900 px (сітка застосунку).
- Ключ референсу — «ім'я + розмір + дата зміни». Якщо файл перезберегти в редакторі, для інструмента це новий референс, а старі тези лишаються з міткою «немає файлу».
- Повний список відомих проблем із кодового огляду — у [docs/ROADMAP.md](docs/ROADMAP.md).
