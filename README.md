# Ref Board

Ref Board — локальний інструмент для розбору візуальних референсів (скриншотів UI): ви переглядаєте картинку, позначаєте на ній ділянки з коментарями (тези), оцінюєте референс за характеристиками, витягуєте палітру, а результат експортуєте в JSON (і за потреби з кропами виділень для аналізу агентом).

**Статус: робочий v1 за концептом.** Один файл `ref-board.html` (vanilla JS, без збірки й залежностей) плюс окремий скрипт `color-test/extract-colors.js` для палітри. Є вбудований самотест (`?selftest=1`).

## Навіщо

Тези самі по собі мало що дають. Цінність з'являється, коли їх зіставляють з картинкою і з іншими референсами. Тому інструмент зберігає структуровані дані (виділення, вердикти, причини, палітру), а узагальнення робить агент або людина на основі експорту. Мета — перенести перевірені прийоми (токени кольорів, типографіка, патерни компонентів) у дизайн-систему застосунку.

Інструмент самодостатній: нічого не імпортує з проєкту і нічого в ньому не змінює. Проєкт отримує лише експортований файл.

## Швидкий старт

1. У папці `tools/ref-board` запустіть сервер:
   ```
   python3 -m http.server 8000
   ```
2. Відкрийте в Chrome або Edge `http://localhost:8000/ref-board.html`.
3. Натисніть «Обрати папку», вкажіть папку з референсами й дайте дозвіл на читання і запис.

Наступного разу натисніть «Відновити доступ» (потрібен жест користувача). Без дозволу на запис експорт піде в Downloads.

**Чому сервер.** `showDirectoryPicker` працює лише в безпечному контексті (`localhost` або `https`), а `localStorage` прив'язаний до адреси: `localhost:8000` і `127.0.0.1:8000` це різні сховища. Скрипт витягування кольорів у Web Worker теж потребує http(s); без нього палітра рахується в головному потоці.

**Без вибору папки (Firefox, Safari).** Додавайте картинки кнопкою «Додати файли» або перетягуванням. Після перезавантаження файли треба додати знову, тези збережуться (привʼязка за ключем файлу, див. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)).

## Перевірка

- Самотест (юніт-перевірки в самій сторінці, не чіпає реальні дані):
  ```
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
    --virtual-time-budget=1000000 --dump-dom "http://localhost:8000/ref-board.html?selftest=1"
  ```
  У виводі шукайте `SELFTEST PASS` або `SELFTEST FAIL` (елемент `#selftest-result`). У браузері достатньо відкрити `?selftest=1`. Малий `--virtual-time-budget` (наприклад 15000) може обрізати асинхронні перевірки, тоді результат лишиться `SELFTEST RUNNING`.
- Демо з тестовими даними: `?demo=1&tab=theses|ratings|color` (картинка генерується на льоту, дані в окремому ключі `ref-board:test`).

## Структура репозиторію

```
ref-board/
├── README.md, CHANGELOG.md, .gitignore
├── ref-board.html             інструмент (один файл)
├── Ref Board.json             експорт даних оцінювання (у .gitignore, не публікується)
├── screenshots/               скриншоти інтерфейсу (демо-дані)
├── concept/                   статичний макет інтерфейсу (власні зображення в concept/assets/)
├── color-test/                алгоритм палітри (extract-colors.js підключається в ref-board.html)
└── docs/                      PLAN, ARCHITECTURE, DATA-MODEL, COLOR-EXTRACTION, UI-CONCEPT, ROADMAP
```

Картинки референсів у репозиторій не входять. Скрипти `color-test/` беруть папку з ними з параметра `--ref-dir`, змінної `REF_BOARD_REFS` або поля `_dir` у локальному `color-test/refs.local.json`; макет `concept/` використовує власні зображення з `concept/assets/`.

## Обмеження

- Повна функціональність лише в Chromium (Chrome, Edge).
- Картинки не зберігаються в браузері, лише метадані (`localStorage`, ~5 МБ).
- Мінімальна ширина вікна 900 px.
- Реальний вибір папки, дозволи, запис у папку і drag-and-drop перевірялись лише логікою, а не в живому браузері людиною; див. [docs/ROADMAP.md](docs/ROADMAP.md).
