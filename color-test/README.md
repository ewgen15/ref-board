# Витягування палітри (color-test)

- Python (еталон): `python3 extract_palettes.py` читає картинки референсів (папка: `--ref-dir`, змінна `REF_BOARD_REFS` або поле `_dir` у локальному `refs.local.json`) і пише `palettes.json` та `palettes_preview.png`.
  Опції: `--rect x,y,w,h` (відсотки), `--detail-side N` (довша сторона великої копії, за замовчуванням 800), `--hi-res` (велика копія = повний розмір), `--no-remove-bg`, `--no-margins`, `--center`, `--edge-only`, `--before <json>` (колонка «до» у превʼю), `--dump-bins DIR`.
- JS (браузер і node, без залежностей): `extract-colors.js`, функція `extractPalette(imageData, {rect, margins, center, edgeOnly, removeBackground, detailSide, hiRes})`. Для картинки з файлу: `ColorExtract.imageDataFromSource(file, 800)` (`null` = повний розмір).
- Тест паритету: `python3 extract_palettes.py --dump-bins <тмп>` (дампи названо за ідентифікаторами), далі `node test_node.js <тмп>`. Результат v5.1: 36/36 прогонів (6 референсів × 6 варіантів), ролі збігаються, max Δhex = 0. Додатково для всіх 13 референсів у варіанті за замовчуванням: 13/13 однакових палітр (ця перевірка разова, у репозиторії її немає). Дампи `.bin` створюються з картинок референсів і в репозиторій не кладуться.
- Формат виходу: `{"ref_NN": [{"hex": "#rrggbb", "share": 0.286, "role": "background|surface|accent|textPrimary|textSecondary|other"}]}`, відсортовано за часткою. `share` — частка площі (для вилучених фону/поверхні — від усієї картинки, для решти — від залишку).
- Обмеження: фото, градієнти, мокапи на кольоровому тлі дають хибні textPrimary/surface; для таких картинок використовуйте `rect`.
- Браузер: canvas `getImageData` не працює з картинками з чужого домену (tainted canvas); завантажуйте через File/Blob.
- Python і JS можуть відрізнятися в зменшенні (Pillow BILINEAR проти canvas), тому паритет перевірено на однакових уже зменшених дампах; зменшення «box» (200 і 800 px) однакове в обох мовах.
- Шрифти не визначаються (поза межами v1).

## Алгоритм v5.1: фон за периметром + акцент, що збігається з фоном

Попередня версія v4 — у git (коміт `9f1d148`, файли `color-test/extract_palettes.py`, `extract-colors.js`) і в `prev_v4/palettes.json` (вихід v4 для порівняння). `prev_v3/` — копія v3. `prev_v5/` — копія коду і виходу v5 (перед змінами v5.1).

v5.1 = v5 (фон за периметром) + одна зміна в пошуку акценту (крок 7). Вибір фону, hex, поверхня і текст не змінені.

Зміна v5.1 (пошук акценту). Проблема v5: лайм `#bbf247` у ref_10–ref_12 — це справжнє поле по краю (фон), але той самий колір є і акцентом (кільце прогресу, кнопка). Старий пошук виключав кольори, близькі до фону, і акцент зникав.
- Кандидат може бути близьким до фону: ΔE ≤ `ACC_GROUP_DE` (12) від фону. Для такого кандидата поверхня не перешкоджає (`far_mask(surf)` або `near_bg`). Далекі від фону кандидати обробляються як раніше.
- Для кандидата, близького до фону (`bgl`), пляма, що торкається крайової смуги `EDGE_BAND`, **не рахується**: поле по краю дає одну велику пляму, яка торкається краю, тож не проходить вимогу «≥ 2 плями». Вимога «≥ 2 плями» лишається: тепер це мають бути окремі плями всередині кадру.
- Частка такого акценту рахується з пікселів зарахованих плям (а не з усієї площі кольору, яка включає поле по краю).
- Нових порогів не додано: використано `ACC_GROUP_DE`, `EDGE_BAND`, `ACC_MIN_BLOBS` і `ACC_MIN_BLOB_PX` з v5.
- Python і JS реалізовано однаково (`extract_palettes.py`, `extract-colors.js`), паритет перевірено.

Решта алгоритму v5 (нижче, кроки 1–8) без змін.

### Алгоритм v5 (основа v5.1)

1. Дві копії (як у v4): мала (200 px) для кластерів і часток, велика (800 px або повний розмір з `--hi-res`) для точних hex, акценту і тексту.
2. Прозорі пікселі ігноруються; білі поля по краю (≥ 245 і зв'язані з межею, якщо їх < 15 % площі) відсіюються.
3. k-means (k = 8, 10 ітерацій, Lab), злиття кластерів з ΔE < 8.
4. **Фон (v5): кластер з найбільшою часткою смуги по краю кадру.** Смуга — товщина `EDGE_BAND` (3 %) по кожній стороні малої копії. Кожен кошик знає, скільки його пікселів лежить у смузі; кластер сумує ці ваги. Фон = кластер з найбільшою сумою смуги. При нічиїй береться найбільший (перший за часткою). Новий поріг не вводився.
   - Далі як у v4: якщо фон > 50 % площі, його пікселі вилучаються (`removed: true`), частки решти рахуються від залишку, другий прохід поверхні за потреби.
5. Плоский піксель: усі 8 сусідів у 3x3 відрізняються max Δканалу ≤ 4. Краї кадру не плоскі.
6. Hex кластера = мода точного RGB серед плоских пікселів великої копії, найближчих до центру кластера (запасний варіант: центроїд).
7. Пошук акценту (велика копія): як у v4, плюс правило v5.1 про колір, близький до фону (див. вище).
8. Поверхня: найближчий до фону (нового) кластер з часткою > 5 %. Тексти: як раніше.

Для 7 з 13 референсів периметр і найбільший кластер збігаються, і вихід не змінився (ref_02, ref_03, ref_05, ref_06, ref_07, ref_09, ref_13 Design). Для 6 референсів фон змінився, це і є суть правки v5: ref_01, ref_04, ref_08, ref_10, ref_11, ref_12.

## Розмітка градієнтів (`ground_truth_gradients.json`), чернетка

Окремий файл для майбутнього детектора градієнтів. Старий `ground_truth.json` не змінено.

- Ключ — ідентифікатор референсу (`ref_NN`). Значення: `{status: "draft", gradient_background: bool, regions: [...], not_gradient: [...]}`.
- `regions` — значущі градієнтні області: `{rect: {x, y, w, h}, type: "linear"|"glow"|"unknown", ends: [hex, hex], angle, is_background, note}`. Прямокутник у відсотках картинки. `ends` — кінцеві кольори, медіана вікна біля заданої точки. `angle` — лише для `linear`: 0 = зліва направо, 90 = зверху вниз (від `ends[0]` до `ends[1]`), інакше `null`. `glow` — світіння (центр → край, `ends[0]` = центр). `unknown` — складні текстури, кінці взяті наосліп, лише орієнтир.
- `not_gradient` — гладкі, але не градієнти: розмиті фото, ілюстрації, 3D-рендери. Детектор має їх відсіювати.
- Стан: чернетка. Координати і кінці перевірено візуально по `ground_truth_gradients_check.png` (сині прямокутники — градієнти, червоні — not_gradient), але не піпеткою в людини.
- Градієнтний фон (`gradient_background: true`) у 2 референсах: ref_08 (небо синій → персиковий) і ref_02 (багатоцентрове бірюзове світіння). Градієнтні плитки (не фон) у ref_01 та ref_07. У решті фон плоский або розмитий фото-фон.
- ref_08: **старий еталон фону `#7fb3cf` у `ground_truth.json` хибний** (точка (10, 8) лежить на градієнті неба). Нові кінці: `#79b1cd` (верх) і `#fdf3e6` (низ). Старий еталон варто замінити пізніше, в окремому рішенні.
- `evaluate_gradients.py` лише читає `ground_truth_gradients.json` і друкує підсумок розмітки. Детектора ще немає, тому оцінки немає.

## Як запустити

Потрібні Python 3 з `numpy` і `Pillow`, папка з картинками референсів (див. вище), а для тесту паритету ще Node.js.

```
cd tools/ref-board/color-test
python3 extract_palettes.py                 # палітри → palettes.json і palettes_preview.png
python3 evaluate.py                         # метрики проти ground_truth.json
python3 evaluate.py prev_v4/palettes.json   # метрики стартової лінії
python3 evaluate_gradients.py               # підсумок розмітки градієнтів
python3 extract_palettes.py --dump-bins DIR # дампи великих копій для JS
node test_node.js DIR                       # паритет JS і Python
```

Опції Python: `--rect x,y,w,h`, `--detail-side N`, `--hi-res`, `--no-remove-bg`, `--no-margins`, `--center`, `--edge-only`, `--before <json>` (колонка «до» у превʼю). Для `evaluate.py` картинки не потрібні: достатньо `ground_truth.json` і `palettes.json`.
